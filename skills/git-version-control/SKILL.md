أوامر Git والتفريع واستعادة العمل الضائع.

## الخطوات
1. قبل أي أمر خطِر افحص الحالة بـ `git status` و`git log --oneline -5`، وأنشئ فرع أمان (`git branch backup-before-fix`). كل ما أُودع تقريبًا يمكن استعادته بـ `git reflog`.
2. التراجع بأمان:
   - آخر إيداع مع إبقاء التغييرات: `git reset --soft HEAD~1`.
   - إيداع دُفع أو شورك: `git revert <sha>` يضيف إيداعًا جديدًا؛ ولا تُعِد كتابة تاريخ مشترك أبدًا.
   - إهمال تعديلات غير مودعة في ملف: `git restore <file>` (هدّام، فتأكد أولًا).
   - استعادة فرع محذوف أو `reset` خاطئ: `git reflog` ثم `git branch rescue <sha>`.
3. تعارضات الدمج: `git status` يسرد الملفات؛ في كل كتلة تعارض احتفظ بالمزيج الصحيح من الجانبين بدل اختيار أحدهما عشوائيًا، واحذف العلامات، وشغّل الاختبارات، ثم `git add` و`git merge --continue` (أو `git rebase --continue`). وللعودة إلى البداية `--abort`.
4. أعد القاعدة (rebase) للفروع الخاصة فقط، وبعد إعادة قاعدة فرعك استخدم `git push --force-with-lease`، لا `--force` المجرد أبدًا.
5. الإيداعات: صغيرة ومركزة، بعنوان بصيغة الأمر ("Fix rounding in invoice totals") والسبب في المتن. وأبقِ ناتج البناء ومجلدات الاعتماديات والملفات الثنائية الكبيرة وملفات الاعتماد خارج المستودع عبر `.gitignore`.
6. التفريع: فروع ميزات قصيرة العمر من `main`، وطلبات دمج بمراجعة وCI ناجح، وحذف الفروع بعد الدمج، ووسم الإصدارات (`v1.4.0`).
7. أي بيانات اعتماد أُودعت يومًا يجب إبطالها واستبدالها؛ حذفها في إيداع لاحق يُبقيها في التاريخ.

## شكل الجواب
الأوامر بالضبط وبالترتيب، وما يفعله كل منها، وأيها لا يمكن التراجع عنه.

## ما أحتاجه منك
- مخرجات `git status`، وما الذي حدث بالضبط، وهل دُفع العمل إلى المستودع البعيد.

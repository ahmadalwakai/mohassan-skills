ملفات README وتوثيق الواجهات البرمجية وأدلة المستخدم وغيرها من الكتابة التقنية.

## الخطوات
1. اكتب لقارئ وهدف محددين: مطور جديد يجهّز المشروع، أو مستهلك للواجهة يدمجها، أو مستخدم نهائي ينجز مهمة. وضع ما يحتاجه أولًا.
2. ترتيب README: وصف في فقرة (ما هو ولمن) ← بداية سريعة تعمل عند نسخها (المتطلبات بإصداراتها، والتثبيت، والإعداد، والتشغيل) ← أمثلة الاستخدام ← مرجع الإعدادات (كل متغير بيئة بمعناه وقيمته الافتراضية ومثال) ← الاختبارات ← النشر ← حل المشكلات ← المساهمة والترخيص.
3. كل أمر ومثال كود كامل ومجرَّب، ويُظهر مخرجاته المتوقعة، ويسمّي نظام التشغيل حين تختلف الأوامر.
4. مرجع الواجهة لكل نقطة: الطريقة والمسار، والغرض، والمصادقة، والمعاملات (الاسم، والنوع، والإلزام، والوصف)، ومثال طلب، وأمثلة استجابة للنجاح ولكل خطأ، وحدود المعدل. ولّده من OpenAPI حين يمكن وأبقه متزامنًا مع الكود.
5. الأدلة تتبع المهمة: خطوات مرقمة بفعل واحد لكل خطوة، ولقطات شاشة حيث تفيد فقط، والنتيجة التي يجب أن يراها المستخدم بعد الخطوات المهمة.
6. اشرح لماذا في القرارات المهمة (ملاحظات المعمارية وسجلات القرار)، لا ماذا فقط.
7. الأسلوب: جمل قصيرة، والمبني للمعلوم، ومصطلحات ثابتة، وعناوين تطابق ما يبحث عنه الناس، وشرح للمصطلحات الفنية.
8. سجل التغييرات: الإصدار، والتاريخ، وأقسام للمضاف والمعدّل والمصلَح والمحذوف، مع ملاحظات الترحيل للتغييرات الكاسرة.
9. استخدم قيم أمثلة وهمية بوضوح، ولا بيانات اعتماد حقيقية أبدًا.

## شكل الجواب
المستند بصيغة Markdown بعناوينه، جاهزًا للإيداع.

## ما أحتاجه منك
- المشروع أو الواجهة المراد توثيقها، والقارئ المستهدف، والكود أو الأوامر الحالية.
